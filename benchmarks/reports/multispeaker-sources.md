# Multi-speaker Benchmark Source: AMI ES2004a

Last verified: 2026-08-07

## Recommendation

Use **AMI meeting `ES2004a`** as the first multi-speaker regression sample.

- It is a four-speaker scenario meeting in AMI's official `SC` unseen/test
  partition.
- The directly downloadable mixed-headset WAV is 16 kHz, mono, 16-bit PCM,
  1,049.354688 seconds long (about 17 minutes 29 seconds), and 33,579,394
  bytes.
- AMI provides manually produced, speaker-separated orthographic transcripts
  in NXT XML. Word timings are generated by forced alignment; the transcript
  and reviewed speech segments are manual.
- A pinned AMI diarization benchmark setup provides ready-to-score
  words-only RTTM and UEM files derived from AMI manual annotations.

Official AMI partition documentation:
https://groups.inf.ed.ac.uk/ami/corpus/datasets.shtml

Official meeting/signal metadata:
https://groups.inf.ed.ac.uk/ami/corpus/signals.shtml

## Formats

### NXT word transcript

Each speaker has one XML file. Lexical items are `<w>` elements with
`starttime` and `endtime` attributes:

```xml
<w nite:id="ES2004a.A.words0"
   starttime="0.37"
   endtime="0.95">Hmm</w>
```

Punctuation is represented by `<w punc="true">`, while non-lexical events use
elements such as `<vocalsound>` and `<gap>`. For a words-only WER reference:

1. Read the four `words/*.xml` files.
2. Keep lexical `<w>` elements that are not marked `punc="true"`.
3. Exclude `<vocalsound>`, `<gap>`, `<nonword>`, and other non-lexical nodes.
4. Preserve each speaker's chronological word order.
5. Retain word `starttime` and `endtime` for timestamp-error measurement.

AMI documents that transcripts were produced in two or sometimes three
passes, are verbatim, distinguish speakers by microphone/channel, and have
word timings generated by forced alignment:
https://groups.inf.ed.ac.uk/ami/corpus/transcription.shtml

Speaker mapping from `corpusResources/meetings.xml`:

```text
A -> MEO015 -> UI
B -> FEE013 -> PM
C -> MEE014 -> ID
D -> FEE016 -> ME
```

Use the global speaker IDs (`MEO015`, `FEE013`, `MEE014`, `FEE016`) in the
generated reference segments so they match the RTTM speaker field.

### RTTM

RTTM is whitespace-delimited, one speaker turn per line:

```text
SPEAKER ES2004a 1 0.37 1.39 <NA> <NA> MEO015 <NA> <NA>
```

The relevant fields are record type, file ID, channel, onset, duration, and
speaker ID. The dscore documentation gives the complete ten-field definition:
https://github.com/nryant/dscore#rttm

### UEM

UEM specifies the regions that are scored:

```text
file_id channel onset offset
```

For this sample there is one region covering the complete WAV. Format
definition:
https://github.com/nryant/dscore#uem

## Metric Definitions and Recommended Settings

### DER

DIHARD defines diarization error rate as:

```text
DER = (false alarm + missed speech + speaker error) /
      total reference speaker time
```

It uses the optimal reference/system speaker mapping. The strict DIHARD
condition applies no forgiveness collar and includes overlapping speech.
Primary evaluation plan:
https://dihardchallenge.github.io/dihard3/docs/third_dihard_eval_plan_v1.2.pdf

Recommended repository settings:

```json
{
  "collar_seconds": 0.0,
  "skip_overlap": false,
  "regions": [[0.0, 1049.354687]]
}
```

This also avoids ambiguity in JER handling when a non-zero collar is used.
For comparison with older AMI recipes, optionally report a separately named
DER with a 0.25-second collar; do not replace the strict result with it. The
AMI benchmark setup's documented examples include 0.25-second and zero-collar
variants:
https://github.com/BUTSpeechFIT/AMI-diarization-setup#scoring

### JER

Jaccard error rate first finds a one-to-one optimal speaker mapping. For each
reference speaker it computes:

```text
speaker JER = (false alarm + miss) /
              duration(reference union mapped hypothesis)
```

The final JER is the unweighted average over reference speakers. An unmatched
reference speaker receives an error of 1.0. JER cannot exceed 100% and may
under-penalize unmapped hypothesis speakers, so it should be reported with
DER rather than alone. Primary definitions:

https://dihardchallenge.github.io/dihard3/docs/third_dihard_eval_plan_v1.2.pdf

https://github.com/nryant/dscore#jaccard-error-rate

### Speaker-attributed WER

For a combined diarization-plus-ASR score, use the CHiME-7 DA-WER procedure:

1. Obtain the global hypothesis-to-reference speaker mapping from DER.
2. Apply that mapping to hypothesis speakers.
3. Concatenate each speaker's words in chronological order.
4. Compute per-speaker edit counts and sum substitutions, deletions, and
   insertions before dividing by the total number of reference words.
5. Charge unmatched hypothesis speakers as insertions and unmatched reference
   speakers as deletions.

CHiME-7 describes this as speaker-attributed WER and calls the resulting
metric diarization-attributed WER (DA-WER):
https://www.chimechallenge.org/challenges/chime7/task1/index

Its primary scoring implementation reuses the DER Hungarian mapping and then
concatenates words by speaker:
https://github.com/espnet/espnet/blob/master/egs2/chime7_task1/asr1/local/da_wer_scoring.py

Report `cpWER` as an additional lexical diagnostic, not as a substitute for
speaker-attributed WER: cpWER chooses the speaker permutation that minimizes
word errors and can therefore conceal diarization mistakes.

## Exact Acquisition Steps

The commands below download only one audio file, the official annotation
archive, and the two pinned scoring files:

```bash
sample=benchmarks/ami/ES2004a
mkdir -p "$sample/audio" "$sample/reference" "$sample/source"

curl -fL --retry 3 \
  https://groups.inf.ed.ac.uk/ami/AMICorpusMirror/amicorpus/ES2004a/audio/ES2004a.Mix-Headset.wav \
  -o "$sample/audio/ES2004a.Mix-Headset.wav"

curl -fL --retry 3 \
  https://groups.inf.ed.ac.uk/ami/AMICorpusAnnotations/ami_public_manual_1.6.2.zip \
  -o "$sample/source/ami_public_manual_1.6.2.zip"

ref_commit=2509d8933721023fab4def2618aabd5c28eb82e9
curl -fL --retry 3 \
  "https://raw.githubusercontent.com/BUTSpeechFIT/AMI-diarization-setup/$ref_commit/only_words/rttms/test/ES2004a.rttm" \
  -o "$sample/reference/ES2004a.rttm"
curl -fL --retry 3 \
  "https://raw.githubusercontent.com/BUTSpeechFIT/AMI-diarization-setup/$ref_commit/uems/test/ES2004a.uem" \
  -o "$sample/reference/ES2004a.uem"
```

Extract only the files needed to generate the repository's reference segment
JSON:

```bash
python3 - "$sample/source/ami_public_manual_1.6.2.zip" "$sample/source" <<'PY'
import sys
from pathlib import Path
from zipfile import ZipFile

archive = Path(sys.argv[1])
destination = Path(sys.argv[2])
members = [
    "words/ES2004a.A.words.xml",
    "words/ES2004a.B.words.xml",
    "words/ES2004a.C.words.xml",
    "words/ES2004a.D.words.xml",
    "corpusResources/meetings.xml",
    "LICENCE.txt",
]
with ZipFile(archive) as source:
    for member in members:
        source.extract(member, destination)
PY
```
