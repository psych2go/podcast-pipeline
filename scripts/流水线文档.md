# 播客处理流水线 v4 · 完整技术文档

## 一、整体架构

v4 起，讲稿生成由 **Claude Code 终端在对话中直接完成**，不再调用任何外部 LLM API。
process.py 只负责"抓取"和"TTS"两端的自动化。

```
原始素材（mp3 / URL / 转录文件）
       │
       ▼
  ┌────────────────────────────────┐
  │  scripts/process.py 入口       │
  │  抓取端（自动）                 │
  └────────────────────────────────┘
       │
       ▼
  ┌────────────────────────────────┐
  │  scripts/fetcher.py            │
  │  获取转录（自动降级）           │
  │  mp3 → Whisper large-v3-turbo  │
  │      （默认，可选 + 说话人分离）   │
  │  URL → curl / httpx / playwr.  │
  │  + 幻觉清洗                    │
  └────────────────────────────────┘
       │  写出 原始转录.txt，停下
       ▼
  ┌────────────────────────────────┐
  │  Claude Code 终端（交互）       │
  │  读 原始转录.txt                │
  │  按 scripts/纠错提示词.md        │
  │  写 转录_纠错.txt（英文纠错）    │
  └────────────────────────────────┘
       │
       ▼
  ┌────────────────────────────────┐
  ┌────────────────────────────────┐
  │  Claude Code 终端（交互）       │
  │  读 转录_纠错.txt（无则原始转录）│
  │  按 scripts/讲稿提示词.md        │
  │  直接写 讲书稿.md               │
  └────────────────────────────────┘
       │  讲稿落盘后
       ▼
  ┌────────────────────────────────┐
  │  scripts/process.py --tts-only │
  │  TTS 端（自动）                 │
  └────────────────────────────────┘
       │
       ▼
  ┌────────────────────────────────┐
  │  scripts/tts.py                │
  │  Fish Audio TTS                │

       ▼
```

## 二、模块说明

### scripts/config.py

加载 `.env` 配置，提供 `FISH_KEY`、`FISH_VOICE`、`BASE_DIR` 等。v4 起 `DEEPSEEK_KEY` 改为可选（讲稿生成不再依赖外部 LLM）。

### scripts/fetcher.py

- URL 抓取（RSS → curl_cffi → curl → httpx → trafilatura → 正则 → playwright, 逐步降级）
- mp3 转录（faster-whisper）+ `clean_whisper_hallucinations()` 清幻觉
- 本地转录文件读取（.txt / .json）

### scripts/html_gen.py

将 `讲书稿.md` 转为精美、自包含的 HTML 阅读页面：

- **解析**：按 `## ` 章节标题拆分，引言段保留为开场
- **布局**：固定侧边栏目录（移动端切换式）、章节锚点导航、滚动高亮当前章节
- **视觉**：铜色暖调纸张主题、衬线/无衬线中西混排、首字母下沉、入场动画
- **响应式**：1280px+ 侧边栏常驻，1024px 以下折叠式汉堡菜单，640px 以下调整字号
- **自包含**：所有 CSS/JS 嵌入 HTML 文件内，无外部依赖

库接口：`from html_gen import md_to_html; md_to_html(md_path)`

CLI：
```bash
python scripts/html_gen.py "content/播客名/讲书稿.md"
python scripts/html_gen.py "content/播客名/讲书稿.md" -o "output.html" --title "播客名"
```

### scripts/legacy/generator.py（LEGACY）

⚠ v4 起不再被 process.py 调用，保留仅供回溯 / 恢复 API 自动生成时复用。讲稿生成改由 Claude 按 `scripts/讲稿提示词.md` 直接完成。原函数：`call_deepseek()` / `generate_outline()` / `generate_briefing()` / `chunk_transcript()` / `get_system_prompt()` / `estimate_speaker_count()`。

### scripts/讲稿提示词.md（v4 核心）

Claude 终端直接生成讲稿时遵循的规则：内容铁律、开场策略、说话人处理、TTS 听觉节奏、英文/数字归一、输出格式、交付前自检。

### scripts/validator.py

- `validate_and_fix()` — 检查并修复：`## ##` 双标题、`###`、`**`、`——`、`---`、代码块、树形图符号、私人化收尾、篇幅偏短
- `smart_chunk()` — 按句子边界切片

### scripts/html_gen.py

- `md_to_html()` — 将讲书稿.md 转为精美 HTML，返回 HTML 文件路径

### scripts/tts.py

- `synth_chunk()` — 单段调用 Fish Audio API（仅 429/5xx/网络错误重试，401/403/400/422 立即抛出）
- `synth_chunks_concurrent()` — 单节内多 chunk 并发合成（默认 3，`TTS_CONCURRENCY` 可调）
- `split_sections()` — 按 `## ` 切分章节，首个 `##` 之前的引言段保留为开场（不再丢弃）
- `normalize_for_tts()` — 朗读前清理不可见字符与冗余空白
- `merge_mp3s()` — ffmpeg concat 合并，章节之间插入 ~0.8s 静音（自动探测格式），回退裸拼接
- `run_tts()` — 库接口，支持断点续传（默认）/`fresh` 全量重生、`read_titles` 朗读章节标题
- `cli_main()` — 独立 CLI 入口：`python scripts/tts.py input.md [output_dir] [--fresh] [--no-titles] [--concurrency N]`

## 三、用法（v4：抓取与 TTS 分两步，讲稿由 Claude 写）

### 第 1 步：抓取转录（自动）
```bash
# URL 可省略 --name：自动从页面 <title> 提取原标题命名文件夹
python scripts/process.py "https://youtu.be/XXX"
python scripts/process.py "https://..." --fetch-only            # 明确只抓不跑 TTS
# mp3 / 本地转录文件无标题可提取，需手填 --name
python scripts/process.py "path/to/audio.mp3" --name "播客名"
python scripts/process.py "path/to/audio.mp3" --name "播客名" --asr-quality max  # 最高精度
python scripts/process.py --transcript "path/to/transcript.txt" --name "播客名"
```
脚本会写好 `content/<标题>/原始转录.txt` 然后停下，提示下一步。
**命名约定**：文件夹与最终 MP3 都用原始标题命名（URL 自动提取，mp3/转录文件用 `--name`）；`? * : [ ] | \` 等文件系统/shell 不安全字符会被 `sanitize_title()` 清掉，保留逗号/空格/中文。

### ASR 质量预设

mp3 转录时可用 `--asr-quality` 选择精度/速度：

| 预设 | 模型 | Beam | 特点 | 速度 |
|------|------|------|------|------|
| `fast` | medium | 5 | 清楚音频快速出稿 | ~3× |
| `balanced`（默认） | large-v3 | 8 | 质量优先，抗幻觉参数调优 | 1× |
| `max` | large-v3 | 12 | 最高精度 + 词级时间戳 + ngram 循环抑制 | ~0.5× |

**`max` 模式**额外启用：词级置信度支持、更低的压缩比阈值（防循环重复）、4-gram 重复抑制、VAD 门槛压低以捕获远场语音。

### 自动 initial_prompt

Whisper 最大的弱点是专有名词错听（人名/产品名/术语）。现在系统会**从播客标题自动生成** `initial_prompt`，条件化解码器让人名保持一致。用户也可手传更强力的 `--initial-prompt`，手动传的优先级更高。

### 第 2 步：Claude 生成讲稿（交互）
在 Claude Code 对话里，让 Claude 读取 `content/播客名/原始转录.txt`，按 `scripts/讲稿提示词.md` 生成 `讲书稿.md`。

### 第 3 步：TTS 出音频（自动）
```bash
python scripts/process.py --name "播客名" --tts-only
# 或直接：
python scripts/tts.py "content/播客名/讲书稿.md"
python scripts/tts.py "content/播客名/讲书稿.md" --speed 1.1 --concurrency 4
```

### 其它开关
- `--asr-quality {fast|balanced|max}`：ASR 质量预设（默认 balanced）
- `--asr-model`：Whisper 模型大小（覆盖预设的模型选择，如 `tiny` 极速测试用）
- `--initial-prompt "..."`：手传初始化提示（自动从标题生成的优先级更低，两者不冲突）
- `--hotwords "Naval,Gary Tan"`：逗号分隔的热词（faster-whisper 1.2+）
- `--force-tts`：清空旧音频重新生成（默认断点续传，失败可接着跑）
- `--no-tts-titles`：不在音频中朗读章节标题
- `--tts-speed`：TTS 语速（默认 1.0）
- `TTS_CONCURRENCY=4`（环境变量）：单节内 chunk 并发数（默认 3）

## 七、技术细节

### 讲稿生成（Claude Code 终端，v4）
- 由 Claude 在对话中直接读 `原始转录.txt`，按 `scripts/讲稿提示词.md` 生成 `讲书稿.md`。
- 不再调用外部 LLM API；超长转录由 Claude 自行分段阅读，保证全文覆盖。
- 交付前按提示词末尾的清单自检（≥3 个 `##`、无 Markdown 符号、篇幅达标等）。

### Fish Audio TTS
- 模型：默认 `s2.1-pro-free`（免费版），可通过 `.env` 的 `FISH_MODEL` 切换（如 `mm3` 付费版）
- 声音：由 `.env` 中的 FISH_VOICE 指定
- 切片：按句子边界，800 字/chunk
- 重试：5 次，间隔递增
- 合并：ffmpeg concat → 裸字节拼接

### faster-whisper ASR
- v5 起改为**回退引擎**（`--asr-engine whisper`）；默认用 Parakeet（见下节）
- 质量预设：`fast`（medium, beam=5） / `balanced`（large-v3, beam=8, 默认） / `max`（large-v3, beam=12 + 全调优）
- `condition_on_previous_text=False`（避免幻觉级联，用 initial_prompt 替代上下文）
- VAD 过滤：threshold=0.4（比默认 0.5 更灵敏），min_speech=500ms，min_silence=300ms
- 抗循环重复：`compression_ratio_threshold` 调低 + `no_repeat_ngram_size=4`（max 模式）
- 幻觉清洗：30+ 规则（Youtube 套话、播客哼哈词、`[Music]` 标签、语言检测幻觉、纯标点行）+ 单词级 n-gram 重复检测
- 自动 initial_prompt：从播客标题提取有信息量的词拼成提示文本，无需用户动手
- `--initial-prompt` / `--hotwords`：用户手传时优先级更高
- 设备：CPU（无 GPU 环境）

### Whisper ASR（v6 默认引擎）
- 模型：`large-v3-turbo`（faster-whisper，CPU int8）
- 内存：峰值 ~2GB（7.7GB 机器上轻松运行，无 OOM 风险）
- 速度：CPU 上 ~1-2× 实时（68 分钟音频约 40-60 分钟完成）
- 接口：`scripts/fetcher.py` 中的 `transcribe_mp3_timestamped()` 和 `transcribe()`
- 专有名词弱点：Whisper 在专有名词上不如 Parakeet 准确，必须搭配 LLM 纠错使用
- 说话人分离：Whisper 也支持通过段级时间戳与 pyannote 对齐

### Parakeet ASR（备用引擎，v5）
- 模型：`nvidia/parakeet-tdt-0.6b-v2`（NeMo，WER 5.39）
- 触发：`--asr-engine parakeet`
- 内存：峰值 ~5.5GB（实测，7.7GB 机器上 OOM 风险高）
- 仅在内存充裕时使用

### 说话人分离（默认启用，可选跳过）
- 模块：`scripts/diarize.py` + pyannote.audio 4.x（speaker-diarization-3.1）
- 触发：`--diarize`（默认启用，需 `.env` 的 `HF_TOKEN`）
- 跳过：`--no-diarize`
- 流程：pyannote 切"说话人×时间" → 按 ASR 片段中点对齐 → 输出 `[SPEAKER_XX]: 文本`
- 注意：说话人分离耗时较长（68 分钟音频约 30-40 分钟），对讲稿质量提升有限；仅在需要精确 speaker attribution 时开启

## 八、当前工作流（v6，2026-08 固化）

> 本节反映当前实际运行状态。CLAUDE.md 是操作入口（步骤 1-9），本节是技术对照。

### 8.1 完整流程（加新播客）

```
1 抓取      process.py <url|mp3>            → 原始转录.txt + 来源.md（保留）
2 纠错关口  Claude 按 纠错提示词.md 分级     → 转录_纠错.txt（或 来源.md 标注免纠错）
3 写讲稿    Claude 按 讲稿提示词.md          → 讲书稿.md（引言段必写/章节400-900字/漏点清单/说话人三级）
3.5 核验    Claude 按「转录对照核验」        → 修改讲稿（重要期推荐）
4 TTS+HTML  process.py --tts-only           → 结构体检 → {播客名}.mp3 + content.html
5 清理      删 转录_纠错.txt / audio/（保留 来源.md）
6 台账      catalog.py add "播客名"
7 site      catalog.py sync-site && gen-index
8 R2        上传 mp3 → 公开 URL（R2_PUBLIC_URL，支持 Range 流式）
9 部署      wrangler pages deploy .（仅 HTML，轻量）
```

### 8.2 新增/变更模块

| 模块 | 职责 | 关键点 |
|------|------|--------|
| `scripts/catalog.py` | 台账 + site.json + 首页 | `add` / `stats` / `sync-site` / `gen-index` / `backfill-sources` / `finish`（一键收尾） |
| `scripts/validator.py` | 讲稿质量 | `validate_and_fix()` 自动修符号；`structure_report()` 结构体检（引言段/章节粒度/SPEAKER残留/中文夹空格，只报告不改） |
| `scripts/config.py` | 配置 | 新增 `R2_PUBLIC_URL`（播放器流式音频基址，空则回退相对路径） |
| `scripts/html_gen.py` | HTML 生成 | 模板改 `.replace()`（解决花括号转义）；内置**音频播放器**（播放/进度/倍速0.5-2x/音量/下载）；输出 `{播客名} - content.html` |
| `scripts/process.py` | 编排 | `detect_briefing()` 兼容 `{播客名} - 讲书稿.md` 命名；`run_html_step` 输出 content.html；ASR 后触发纠错关口提醒 |

### 8.3 R2 公开访问与音频

- 桶 `podcast-audio` 已开启公开访问：`npx wrangler r2 bucket dev-url enable podcast-audio`
- 对象键**不带桶名前缀**：`{播客名}/{播客名}.mp3`
- 公开 URL：`https://{R2_PUBLIC_URL}/{播客名}/{播客名}.mp3`，支持 HTTP Range（206 分片流式播放）
- 播放器在 html_gen 里用 `R2_PUBLIC_URL` 拼绝对 URL；site/ 不再放 mp3，部署轻量
- Cloudflare 认证走 `wrangler login` OAuth，无需 `CLOUDFLARE_API_TOKEN`

### 8.4 讲稿质量新规则（写入 讲稿提示词.md）

- **引言段必写**：2-3 句、50-100 字，只做全局导览
- **章节粒度**：每章 400-900 中文字（目标 500-800），碎片章合并、超长章拆分
- **漏点清单**：动笔前列话题/论点/数据清单，写完对照查漏（删是主动判断，漏是零容忍）
- **说话人三级**：①转录带标签用名字 ②开场点名用名字 ③无标签+不熟+未点名→角色化，禁止编名字
- **转录对照核验**（第 3.5 步）：查脑补、张冠李戴、数字保真、论点覆盖、金句术语
